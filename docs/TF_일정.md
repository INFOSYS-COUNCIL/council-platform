- 출발 상태는 [10월 29일 진행 현황](TF_남은%20일_체크리스트.md)을 기준으로 한다. PR #5는 main에 Merge됐고, dev·prod Migration 3개·기본 배포·Preview 연결은 완료 보고된 상태다. 남은 것은 대시보드 연결·실제 로그인 검증·보호 설정·Secrets 등이다. 완료한 기반을 다시 만드는 일정으로 해석하지 않는다.

## 1. 역할과 주간 리듬

| 담당 | 역할 |
|---|---|
| 한지석 | 기반 작업, Issue 작성·배정, 공용 파일 관리, 최종 리뷰·Merge |
| 강주원·정재헌 | 입력 폼·화면 구성이 많은 기능 Issue |
| 이은규·조수빈 | 데이터 처리·권한 확인·테스트 비중이 큰 기능 Issue |

A팀은 강주원·이은규, B팀은 정재헌·조수빈이다. **모두 화면 하나를 구현·연결·검증까지 맡는다.** 프런트와 백엔드를 나눠 차례로 넘기지 않는다. 리뷰는 강주원 ↔ 정재헌, 이은규 ↔ 조수빈으로 다른 팀끼리 한다.

| 요일 | 팀원 | 리드 |
|---|---|---|
| 목 | 지난주 시연, 이번 주 Issue 확인, 필요한 강의 | Issue 배정·범위·완료 기준 설명 |
| 금~월 | 구현→확인→설명→AI 리뷰 | 다음 주 DB·RLS·함수·타입·경로·공용 부품과 테스트 |
| 화 23:59 | PR 마감 | 누락·막힌 점 확인 |
| 수 | 상호 리뷰, Preview 확인, 수정 | 최종 리뷰, 순차 Squash Merge, 배포 확인·다음 Issue 준비 |

다음 주 기반은 목요일 배정 전에 준비한다. 준비되지 않은 기반에 의존하는 Issue는 배정하지 않는다. 하나를 Merge한 뒤 남은 PR은 최신 main을 반영하고 CI가 다시 통과해야 한다.

첫 주도 가이드대로 **11/3 PR → 11/4 리뷰·병합**이다. 전달받은 “11/4까지 협업 파일 넣기”는 병합 완료 목표로 잡는다. 규칙 파일은 팀원이 AI로 첫 작업을 시작하기 전에 먼저 반영한다.

목표는 “프롬프트에 쓸 단어를 배우기”다. 대상은 비전공자 4명이며 개념을 알고 AI에 정확히 요청하는 수준을 목표로 한다.

각 강의 끝에는 ① 프롬프트 나쁜 예/좋은 예 ② 우리 저장소에서 찾아볼 파일 ③ 확인 질문 3개를 넣는다. 선택 강의 전체를 마쳐야 기능 개발을 시작하는 구조로 만들지 않는다.

## 5. 배정·완료·지연 대응

- 한 Issue는 일주일 이내·15분 안에 리뷰할 크기로 자른다. 목표·담당/다른 팀 리뷰어·수정 가능한 파일·준비된 기반·완료 기준·제외 범위·읽을 강의를 명시한다.
- 같은 파일을 두 사람에게 배정하지 않는다. 화면 수가 모자라면 독립 흐름이나 기존 기능 개선으로 나누며 검증만 맡는 사람을 고정하지 않는다.
- 모든 PR은 가이드 3.3절의 8개 체크리스트를 따른다. 관련 없는 항목은 이유를 남긴다. 버튼이 보이는 것만으로 권한 완료를 판정하지 않는다.
- 기반이 늦으면 리드가 범위를 줄이거나 준비된 작은 Issue를 배정한다. 팀원이 임의로 DB·공용 파일을 바꿔 해결하지 않는다.
- 5~7주차의 병행 개발은 리드의 선행 기반·공용 부품 준비가 전제다. 11/26·12/10에 진척과 학사·개인 일정을 반영해 남은 분량을 재평가한다.
- 공동편집 검증이 11/25까지 통과하지 않거나 필수 범위가 예상보다 크면 11/26에 일정·범위를 다시 결정한다. 장식·추가 필터·부가 자동화를 줄이되 공동편집·파일 권한·기수 권한을 임의로 빼고 완료로 보고하지 않는다.

## 6. 보호 설정 전에 확인할 사항

가이드대로 CODEOWNERS는 `* @hkg109`로 맞췄다. 유일한 Code Owner가 작성한 PR에 Code Owner 승인을 필수로 요구하면 리드 본인 PR의 승인·병합 절차를 별도로 확인해야 한다. GitHub는 PR 작성자의 자기 승인을 허용하지 않는다. 1주차 보호 설정 검증에 이 경우를 포함하고 필요한 운영 정책은 리드가 결정한다. 임의로 다른 Code Owner를 추가하지 않는다.

**10/29 결정:** Code Owner 승인 필수는 유지하고, 리드 본인 PR만 1단계 리뷰어 Approve와 CI 통과를 확인한 뒤 관리자 우회로 Merge한다(가이드 3.1절). Code Owner는 추가하지 않았다.
